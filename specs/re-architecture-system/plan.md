# Plan: re-architecture-system

Input: approved [requirements.md](requirements.md) and [system-design.md](system-design.md); DB design skipped (no schema change). Revised 2026-11-19 after design review.

## Strategy
Strangler, one flow at a time, the system runnable and `make check` green after every task.
- **Copy, then delete (LLM code).** LLM code is *copied* into `agent/` (T10-T13b) while the old engine HTTP app keeps serving it; the API switches flow by flow (T14, T15); the old code is deleted only after the soak gate (T16, T17). Deterministic engine code is *moved in place* (T3-T6) and the legacy HTTP handlers keep calling it; T5 and T6 add adapters on the legacy path, and a T5/T6 revert restores the old signatures with no data impact.
- **Config fallback.** The API wire picks the new gRPC client when `AGENT_ADDR` / `BLUEPRINT_ENGINE_ADDR` is set and the legacy HTTP client (`BLUEPRINT_ENGINE_URL`, default `http://localhost:8090`) otherwise. Rollback of a flow before T16 = unset the variable. Removed in T17.
- **Ports are final from the start.** Agent gRPC :8091, Engine gRPC :8092, both permanent. The legacy HTTP :8090 is deleted in T16; nothing is flipped, so no env copy can point HTTP at a gRPC port. `.env.example` gets the new addresses in T9.
- **Python packages** `fga_engine` and `fga_agent` (no generic top-level names). The engine `pyproject` sets `[tool.uv.build-backend] module-name = "fga_engine"` (T3). `make engine` runs the gRPC server under `watchfiles` for reload (a dev dependency; uvicorn `--reload` is gone).
- **Ratchet for architecture rules.** T2 adds the Python layer rules with an allow-list (`scripts/python-arch-allow.txt`); the rules scan only directories that exist (`blueprint-engine/src/*/{domain,usecase,service}` once T3 creates them, `agent/` once T10 creates it); every re-layering task shrinks the list; T16 requires it empty. Exception decided later: the Engine's multi-Protocol `domain/gateway/__init__.py` (rule `gateway-per-kind`) and its servicer/`mapping.py` shape are refactored after the feature is complete, together with the Go API naming (see `docs/harness/progress.md`), so that single allow-list entry may outlive T16.
- **Test conservation.** T0 records the baseline as collected node IDs (`pytest --collect-only -q`, 210 at 2026-11-19; parametrized cases count individually) in `specs/re-architecture-system/test-map.md`. Every task that moves tests updates the map; T19 verifies every baseline ID is mapped to a collected ID or an explicit, reviewed removal.
- **Soak gate (T16 starts only when all hold):** (1) every flow runs on the new path for one full working day of the author's use; (2) `agent-eval` and `agent-eval-estimate` within one case of the T0 baseline (`baseline/`); (3) `scripts/smoke-replay.sh` and `scripts/smoke-failures.sh` pass on the new path; (4) the user says go. Owner: the user.

## Risks
- **Transient duplication** of LLM code (T10-T15). The old copy is frozen once T11a starts; fixes go to the Agent copy and are back-ported only while the old path is live.
- **LLM behavior drift.** Baselines are recorded in T0 on the untouched stack; any regression blocks the soak gate.
- **gRPC streaming cancellation across two hops** is the least familiar part; T10 builds the cancel token and T13b tests it end to end before the API depends on it.
- **Estimate flow is the riskiest switch** (state, 30 min stream, 40 turns); switched last and soaked.
- **Move size** (`dxf_plan.py` 1k lines, `convert.py` 768): T4b moves them whole behind gateways; if it exceeds 6 h it is split before building.
- **Generated code churn**: marked generated, drift-checked.
- **Python tooling cost** (`buf`, grpcio-tools, watchfiles) on macOS: `init.sh` checks and documents; fallback is `grpcio-tools` for Python and `protoc` for Go from the same proto.
- **Dev-loop change**: no uvicorn `--reload`; watchfiles restarts the gRPC server.
