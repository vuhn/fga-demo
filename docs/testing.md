# Tests

What the unit and integration tests assert.


`tuples_test.go` asserts the pure relation builders: role assignment writes one role and deletes the other three; a crossed affiliation/role pair emits nothing; a product toggle is only the wildcard; a created document or photo emits `tenant`, its folder or album, and `owner`; a created folder or album emits `root` at top level or `parent` below, plus `public` only when public; `Public` is the single visibility marker; grants map `external_users`/`external_admins` to their usersets, reject `internal_users` and editor for `external_users`; remove member deletes the four role relations and the member's direct grants and never a group or marker tuple.

`role_relations_test.go` asserts custom-role tuples: two anchors on create, one `grant_*` userset per permission and no implied permission, and removal of anchors, grants, and assignees. `seed_roles_test.go` asserts the seeded Auditor and Vendor tuples exist and that the seed writes no `assignee` tuple.

`project_integration_test.go` asserts the union (tenant role a+b plus project role c), that external members see nothing in a project they are not in, that internal members reach every project, and that stale project membership fails closed. `entity/company_test.go` asserts name keys and derived affiliation; `seed/world_test.go` asserts seed consistency.

`model_integration_test.go` (build tag `integration`, skips without `OPENFGA_API_URL`) creates a throwaway store, writes `api/fga/model.fga` and the seed tuples from `api/internal/seed`, and asserts with Check and ListObjects:

- Internal members (Bob, Cara) list every Acme folder, including private Company, Board, Specs, and Partners. Cara can edit Secret but not delete it, and cannot change visibility; Bob can.
- External users (Dan) list exactly Client and the shared Partners, and their documents. Legal (public flag under private Board) and Specs/Pricing (private under public Client) stay hidden. Dan cannot edit or create.
- External admins (Fay) create folders but not private ones, upload and edit in Client, edit Client Brief but not delete or share it, delete their own Visit Agenda, and cannot see Specs, Partners, or Company.
- Bob as a Globex external user sees only public Globex content and cannot create.
- Sharing private Board with all external admins lets Fay view Board, Q3 Plan, and Legal but not edit; Dan still cannot.
- Making Client private hides it and its content from Dan and Fay (Fay still sees her own file); making Board and Specs public reveals Board, Legal, Legal Hold, and Pricing.
- Disabling photos blocks every photo check while the owner tuple stays; re-enabling restores access.
- Removing Dan's role tuple removes all access, including the stale Partners share.

Cost estimation (`prds/plans/cost-estimation.md`): `blueprint-engine/tests/test_estimate.py` (scripted LLM, fake price source, no network) asserts the takeoff against hand-computed areas, wall and plaster quantities, that existing rooms are not built and replaced ones add demolition, that a line resting on an assumed fact is `assumed`, structure and MEP lines when in scope, and that a plan with no rooms is `unsupported` rather than zero; the pricing cascade to the dong (overhead, profit, design, contingency raised by the assumed share, VAT), unpriced lines excluded and warned; the price checks (the quote must be on the page and carry the number, unit and currency conversion, outlier dropping, fewer than three sources is low confidence, the region pinned by code, a prompt-injected page cannot move a rate, only the rates' own sources are cited, the cache, no search provider); the interview (the example conversation asks location, then what exists, then the next missing slot and never estimates early; flags a small model sets unprompted do not make the agent assume; "I don't know" is recorded `assumed` and shown in the result; several answers in one message; changing an answer re-prices only what changed; scope changes the total; user rates fill unpriced lines; explaining a line); changing a finished estimate (an item taken out really leaves the lines and the total, the model cannot remove what the message never names, put back, a no-change reply never claims a change, the reply is given exactly what changed); the demo search provider (every rate code priced through the real pipeline, quality moves the rate, estimate labelled DEMO DATA); fixtures (assumed absent and priced, existing ones and finished rooms skipped, loose furniture not priced, the agent asks which exist before pricing, "none"/"all" chips, only fixtures the message refers to, "I don't know" assumes none exist and says so); and the stream (progress, token, fact, question, then done; rate events before the estimate; an LLM failure mid-stream is an `error` event; a dead LLM before any text falls back to the question text). Go `service/estimate_session_test.go`: a turn stores both messages, the state and the estimate together; starting an estimate replaces the blueprint's one session (needs `can_edit`, touches nothing otherwise, keeps the old session when the replace fails); a restart while a turn runs makes that turn 409 and leaves the new session untouched; a turn with no session is 404; denied, invalid, other-tenant and turn-capped requests never reach the engine; an engine error, a client that went away and a concurrent turn (409) write nothing. The engine client test checks that every event is relayed in order, the done outcome and the error mapping. The routes reuse `can_edit` and `can_view`, which `TestBlueprintAccess` already covers; the HTTP smoke checks a viewer gets 403 creating a session or sending a message and 404 reading the session. `make engine-eval` is not extended yet: the live-model checks so far were manual (qwen3 reads Vietnamese price pages correctly and the injected-instruction page was rejected as an outlier).

`blueprint_integration_test.go` creates two blueprints with `BlueprintRelations.Created` (none are seeded) and asserts: internal members view and edit, only the owner or an internal admin manages; externals see nothing without a share (no public chain); a share outside the external's projects fails closed; an editor tuple to an external user still cannot edit and the `external_users` editor group is refused (`cannot_upload`); `can_create_blueprint` follows `can_contribute` (Fay yes, Dan no) and is false in Globex, where the product is off; disabling the wildcard denies every blueprint check while other products stay; removing a member drops a stale share.

`infrastructure/blueprintengine/client_test.go` asserts the engine client against a fake server: 4xx becomes `validation` with the engine's message (or FastAPI's field errors), 5xx or no connection becomes `engine_unavailable`, and a generate result without a model is kept as not built.

`blueprint-engine/tests/` (pytest, run by `make check`; no LLM) asserts the deterministic engine (including `test_convert.py`: the sample plans' PDF and PNG converted to a DXF and read back, areas within 10% of the original; skipped when `blueprint-engine/out/` is absent) on hand-written briefs: layout stability across revisions, entrance rotation, shrink-to-fit, rule checks (including the geometry, collision, information and design rules), edit ops, the agent loop with a scripted fake LLM (retry with error feedback, chat history, reviewer acceptance and guardrails, the opt-in Enhancer), DXF/SVG/PDF output, and the IFC export (element counts, space areas, fixtures contained in their space). `make engine-eval` runs the golden prompts against the live Ollama model (not part of `make check`; `--enhance` turns the Enhancer on). The engine client test in `api/internal/infrastructure/blueprintengine` checks that revise and review send the chat history, and that `ReviseStream` relays progress lines in order, returns the final result, maps an `error` line to the right sentinel, and fails before any callback when the engine answers 4xx. The engine tests assert that thinking is streamed only while a sink listens (mock Ollama transport), the progress events of a scripted revise (including a retry) and the NDJSON shape of `/v1/revise/stream`. DXF import of any file: `tests/test_drawing.py` imports the jscad `dxf-parser` samples (`tests/samples/jscad/`) and checks each renders (SVG, PDF, DXF, IFC), survives a JSON round trip and patches back byte for byte, plus a synthetic file holding every entity kind (curves, hatch, solid, text, point, dimension, leader, nested blocks, hidden layer, ray) and the unit scaling. DXF import: `tests/test_import.py` asserts the engine reads the three reconstructed sample plans with the known room count, areas (within 3%), door and window counts, entrance side, labels (English and Vietnamese) and the angled wall, guesses a unitless file, reads single-line walls, refuses garbage, and serves `/v1/import/dxf`. The Go client test checks the multipart request and the plan parsing; `service` tests check that a brief-less (imported) version refuses review and brief edits, that its chat revision calls the engine's plan edit, keeps `brief` null and writes nothing on an engine error, that a denied or stale revision never reaches the engine (fake gateway, engine and authorizer in `blueprint_reviser_test.go`), and the file validation. Writing edits back: `tests/test_patch.py` imports our own export, applies edits to the model and patches the original, and asserts that nothing changes without edits, that a rename changes only the label, that removing any one door or window still imports as the same rooms (the wall is closed across the gap), that a window keeps its place when widened, that fixtures move, are removed, are copied from a block of the same kind or drawn on `FGA-ADDED`, that unsupported changes are reported as skipped, that the direct edit ops move, turn, slide and refuse what does not fit, and the two endpoints. Go: the client tests check the `plan/edit` and `export/dxf-patch` requests; the `service` tests check that a plan edit stores an `edit` version with a null brief, that denied, stale, brief-plan and malformed requests never reach the engine, that an engine refusal stores nothing, and that the export sends the original bytes with the version-1 and chosen models under a neutral file name (no ids) and is refused without `can_edit`. Creating: `tests/test_patch.py` also asserts that `/v1/generate/plan` returns an imported-style model with provenance and a DXF into which a direct edit is written back, and that an unbuildable brief returns no model and no file; the Go `blueprint_creator_test.go` checks that a create stores version 1 with a null brief and the drawn DXF as the original (name, size, hash) through `CreateImported`, and that a denied or unbuildable create stores nothing and a denied one never reaches the engine. Converting: `tests/test_patch.py` asserts `/v1/plan/draw` keeps the rooms and fixtures of a plan made from a brief, refuses a CAD plan, and that an open plan reads back as fewer spaces with a note (the same conversion was run over all 37 stored legacy versions: all convert); the Go `service` tests check that a conversion stores one version with a null brief and the drawing as the original of the new version (never a plain append), sends the engine only the model and the name, and that denied, stale, other-tenant, already-DXF and engine-refused requests store nothing, that an export older than the file is refused and the original defaults to the newest file; the client test checks the `plan/draw` request. The import and original routes reuse `can_create_blueprint` and `can_edit`, which `TestBlueprintAccess` already covers. The review route reuses `can_edit`, which `TestBlueprintAccess` already covers (viewer share: no edit; editor share and internal members: edit).

`role_integration_test.go` asserts that a bare internal admin is allowed every permission an internal user is, on every Acme object. It also assigns Dan to Acme's Auditor role and asserts he can view private Company, Secret, and All-hands and can view products, and still cannot edit, manage, contribute, manage members, or create a private folder.

`scripts/check-architecture.sh` (run by `make check`) asserts the architecture rules: no Gin, pgx, or OpenFGA SDK imports in `domain`, `usecase`, or `service`; no tuple or object-id literals outside `infrastructure/fga`; no role/affiliation branching in services (stored-invariant files allowlisted); no `but not` or `condition` in `model.fga`; `model.fga` equals the DSL block in `docs/authorization-model.md`; no OpenFGA relation names in web code outside `permissions.tsx` and the Inspector page. Each failure prints what, why, and fix.
